# ClipForge — видеоклипы по запросу

Версия v38. Для каждого заданного запроса сравниваются первые 20 результатов YouTube, включая первый. Оценка: доля слов запроса в названии (до 100), точная фраза в названии (+20), доля слов в описании (до 10). При равной оценке побеждает более ранний результат YouTube. Это сравнение метаданных, без анализа видеокадров. Уже использованные, явно исключённые и обрабатываемые исходники пропускаются. Вторая страница не запрашивается. Если среди 20 нет доступного исходника, проверяется следующая явно заданная строка запроса; если новых роликов нет, подготовка останавливается с понятным сообщением.

Из одного исходника создаётся максимум один клип. Разные ссылки на одно YouTube-видео считаются одним исходником. Повтор прерванного монтажа продолжает ту же запись клипа. Обычный сбой скачивания повторяет тот же адрес через 60 секунд в пределах установленного числа попыток; ручная проверка останавливает скачивание.

Режим пяти видео использует пять разных исходников. Перед отправкой каждого подготовленного ролика требуется просмотр и подтверждение. Старые материалы скрыты в закрытом архиве; аккаунты и квитанции прошлых отправок сохранены. После обновления очередь выключена, запросы и описания пустые.

Миграция базы: `alembic upgrade head` (0010_neutral_sources). Сохраните закрытую резервную копию базы, файлов и секретов перед обновлением. Архивные исходники и задания недоступны для нового монтажа, просмотра и повторного запуска через панель.

## Музыка и монтаж

Автоматический режим сам выбирает трек из загруженной библиотеки, случайную позицию и фрагмент 10–15 секунд, скорость из диапазона 0,98–1,03× с шагом 0,001 без 1× и одно из разрешений 1080p/720p/480p, отличающееся от короткой стороны исходного видео. Выбираются такие параметры, чтобы и исходный фрагмент, и итоговая длительность были в пределах 10–15 секунд. Исходники короче 10 секунд отклоняются. Если доступных треков нет, сохраняется исходный звук; отсутствие музыки не блокирует запуск. Пропавшие до выбора треки также приводят к исходному звуку.

Выбор сохраняется в `resolved_editing` задания до запуска кодирования. Повтор после сбоя использует тот же фрагмент, трек, скорость и качество. Библиотека доступных треков фиксируется при создании задания. Параметры применяются в обычном монтаже, конвейере и режиме пяти видео. Ниже остаются ручные настройки для выключенного авторежима.

В панели «Автоматический монтаж» задаются начало/конец фрагмента по исходному видео, скорость 0,5–2× и качество 1080p/720p/480p. Длина в текущем режиме ограничивает итог после изменения скорости. Полный кадр на размытом фоне 9:16, поиск лучшего из первых 20, описания, подтверждение просмотра и один клип с исходника сохраняются.

В панели нет выбора или загрузки своей музыки. В авторежиме случайно выбирается трек из уже имеющейся библиотеки; при пустой или недоступной библиотеке используется исходный звук. В ручном режиме новый снимок настроек из панели сохраняет исходный звук. При изменении скорости высота тона сохраняется. Доступный выбранный трек полностью заменяет исходный звук и повторяется до конца клипа. Параметры применяются к новым заданиям; повтор монтажа сохраняет ранее выбранный звук и остальные параметры.

Ранее добавленные треки и совместимый API импорта музыки сохраняются. Выбор звука из каталога TikTok в текущем веб-загрузчике не реализован.

Музыка и её выбор включаются в закрытый перенос данных. Секреты доступа не входят в исходную сборку. Новая таблица или миграция для настроек монтажа не требуется.

## Что входит

- `#tiktokWebPanel`: отдельная загрузка через обычный сайт TikTok Studio, без TikTok API публикации.
  Общий импорт JSON понимает cookie домена tiktok.com и создаёт аккаунт типа `tiktok_web`,
  отдельно от OAuth `tiktok`. Поддержаны готовый клип или локальный файл (в этом режиме 5–180 сек.;
  горизонтальный файл предварительно оформляется в 9:16), описание/хэштеги, явное подтверждение
  отправки и видимость Only you/Everyone. При неизвестных элементах UI отправка останавливается;
  CAPTCHA/вход требуют обычного ручного подтверждения с обновлением cookie, не решаются программой.
  Запись файла сохраняется до передачи и до Post; неопределённый результат не повторяется.
  Без ссылки/квитанции публикация не объявляется успешной. Миграция `0009_tiktok_web_receipts`.
  Реальная отправка зависит от действующей сессии, региона и доступного интерфейса TikTok;
  без пользовательской сессии проверяются только локальные браузерные имитации и защита очереди.

- Панель `#loginQueuePanel`: импорт JSON/CSV с `login,password,display_name` для своих аккаунтов,
  до 50 ожидающих записей. Импорт не запускает вход: нажмите отдельную кнопку Start.
  Один браузер, одна попытка на запись, 60 секунд между успешными входами. Ошибка останавливает
  очередь целиком; CAPTCHA/2FA/условия ожидают ручного действия администратора до 15 минут.
  Живое окно проверки отображается только внутри защищённой панели, без открытых CDP/VNC-портов.
  Никаких stealth, смены IP или автоматического решения проверок. Google может отклонить браузер;
  успешный вход не гарантируется. Пароли шифруются в БД, не попадают в API/логи и очищаются после
  успеха/ошибки/отмены/прерванного входа. Ожидающие пароли очищаются отдельной кнопкой.
  После перезапуска незавершённый вход не повторяется: запись нужно импортировать снова.
  Не включайте Playwright tracing, DEBUG=pw:api, HAR или запись браузера с реальными паролями.
  Для сохранения сессии требуется действующий YouTube-канал и подтверждённый интерфейс Studio.
  Миграция `0008_account_logins` добавляет новую таблицу, не изменяя существующие аккаунты.

- Режим 24/7 включается отдельно в панели. Расписание хранится в БД и выполняется worker,
  даже если вкладка закрыта. По умолчанию выключен; аккаунты выбираются только из явно
  отмеченных владельцем каналов. Доступны режим подготовки без публикации и загрузка через Studio.
- Цепочка загрузчиков `direct,cnvmp3,y2save` настраивается через `DOWNLOAD_PROVIDER_ORDER`.
  При технической ошибке пробуется следующий; HTML и пустые файлы не принимаются за MP4.
  CAPTCHA, вход, HTTP 401/403/429 останавливают задачу, а не включают обход проверки.
  Бесплатные внешние сайты могут перестать работать; гарантии их доступности нет.
- Перед отправкой проверяется реальное видео: квадратный/вертикальный кадр, не более 180 секунд.
  Автоматические клипы — 1080×1920; классификацию Shorts выполняет YouTube, не хэштег.
- Один клип на цикл, выбранные каналы, интервал и свой лимит до 3 отправок за скользящие 24 часа.
  Резервации и неопределённые отправки входят в лимит. Сбой поиска/загрузки включает ожидание
  следующего цикла; CAPTCHA, вход, ошибка монтажа или публикации приостанавливают план.
  При свободном месте менее 3 ГБ план останавливается без удаления файлов;
  остановка отменяет ожидающие задачи, но не гарантирует отмену уже начатого сохранения в Studio.

- Один web-процесс и один отдельный worker. Встроенный worker отключён.
- Постоянный локальный Docker volume: SQLite, исходники, клипы, история и receipts отправок.
- Alembic запускается отдельным этапом до web/worker, включая историческую ревизию `0005_connection_hub_id`.
- Chrome + FFmpeg/FFprobe внутри образа; Windows-пути не используются.
- Защищённый DNS настраивается только в выделенных профилях Chrome для YouTube и y2save.
  Системный DNS, Happ и проверка TLS не меняются. Для y2save параметры `Y2SAVE_DOH_ENABLED`,
  `Y2SAVE_DOH_TEMPLATE`, `Y2SAVE_HEADLESS` доступны в `.env`; чужие поля Local State сохраняются.
- Xvfb на обоих процессах: веб-проверка сессии тоже запускает headed Chrome.
- Браузеры запускаются под UID 10001 с Chromium sandbox. Root используется только для начальной
  подготовки файлов/секретов и отдельного административного инструмента backup/restore;
  web, worker и браузер всегда сбрасывают права. Нет privileged, CDP/VNC-портов
  или отключения TLS-проверок. При проблеме sandbox НЕ отключайте его и защиту хоста;
  разберите ошибку на выбранной ОС и повторите smoke.
- Bootstrap получает стандартный `SYS_CHROOT`, чтобы условное правило официального seccomp
  разрешало Chromium выполнить chroot внутри его собственного user namespace. После setuid
  у web/worker/браузера эффективные capabilities равны нулю. Smoke проверяет UID, CapEff,
  NoNewPrivs, seccomp и страницу `chrome://sandbox`; `SYS_ADMIN` не используется.
- Origin/CSRF-проверка, заголовки безопасности, ограничение попыток входа (10/мин на адрес).
  Заголовкам forwarded client IP не доверяем; за Caddy лимит может быть общим для клиентов прокси.
- Проверки здоровья, ограничение размера логов и перезапуск при завершении процесса.
  Docker healthcheck сам по себе НЕ перезапускает зависший процесс и НЕ доказывает публикацию.
- Архив исходников **не содержит `.env`, cookies, базы или паролей**.

На старте используйте один сервер, локальный диск и один worker. Не храните SQLite на NFS/SMB,
не запускайте второй worker с тем же постоянным браузерным профилем. Для горизонтального
масштабирования потребуются PostgreSQL, раздельные профили/lease и отдельный нагрузочный тест.

## 1. Новый пустой сервер

Распакуйте исходники в закрытую папку, например `/opt/clipforge`. Установите Docker Engine/Compose
по документации поставщика вашей ОС. Мы не устанавливаем программы и не меняем firewall автоматически.
Убедитесь, что свободного диска достаточно для исходников, клипов, сборки образа и резервных копий.

В папке сборки:

```sh
python3 -m deploy.init_secrets
python3 -m deploy.manage build
python3 -m deploy.manage start
python3 -m deploy.manage smoke
python3 -m deploy.manage status
```

Первый шаг запросит **новый** пароль администратора и ключ поиска YouTube (можно добавить позже).
Это НЕ пароль Google. Не используйте известный учебный пароль. Генерируются `.env` и закрытая
папка `secrets/`; ничего не выводится в журналы. Без ключа YouTube поиск не работает, но загрузка
вашего готового файла возможна. Если файлы уже существуют, инструмент откажется их заменить.

Для доступа с компьютера откройте SSH-туннель:

```sh
ssh -L 8001:127.0.0.1:8001 USER@SERVER
```

Затем откройте **http://127.0.0.1:8001**, не localhost: это должно совпадать с `PUBLIC_BASE_URL`
для Origin-проверки. Порт панели опубликован только на loopback сервера, база/экран/браузер — не опубликованы.

## 2. Перенос существующих аккаунтов, истории и видео

Не копируйте только клипы: нужно сохранить SQLite и receipts, иначе потеряется защита от дублей.
Не копируйте текущую Windows `.env` целиком: там локальные пути. **Сохраните исходный APP_SECRET**:
без него сервер не расшифрует уже импортированные сессии. Не генерируйте новый ключ для старой базы.

Остановите создание задач, дождитесь пустой очереди и остановите локальный сервис перед экспортом.
Не отменяйте задачи вслепую, особенно если YouTube уже получил Save. Из папки распакованной сборки
локально используйте Python из исходного `.venv` (в нём установлен python-dotenv):

```powershell
C:/PATH/PROJECT/.venv/Scripts/python.exe -m deploy.init_secrets --existing-env C:/PATH/PROJECT/.env
C:/PATH/PROJECT/.venv/Scripts/python.exe -m deploy.data_transfer export --database C:/PATH/PROJECT/data/clipforge.db --media-root C:/PATH/PROJECT/data --output C:/PRIVATE/clipforge-transfer.zip
```

Перенесите `secrets/`, новую `.env` и **приватный** `clipforge-transfer.zip` по SSH/SFTP отдельно
от публичного архива. Не отправляйте их в чат, Git или открытое хранилище. На Windows ограничьте доступ
правами NTFS своей учётной записи; chmod там не гарантирует Unix-права. На Linux папка secrets должна
иметь права 700, файлы — 600. Подготовленные секреты читает только root bootstrap контейнера, после
чего копирует их в приватную tmpfs и передаёт процессу UID 10001.

На **пустом** серверном volume сначала восстановите данные, потом запускайте миграции и приложение:

```sh
python3 -m deploy.manage build
python3 -m deploy.manage restore --archive /PRIVATE/clipforge-transfer.zip
python3 -m deploy.manage start
python3 -m deploy.manage smoke
python3 -m deploy.manage status
```

Экспорт не изменяет оригинальную БД. SQLite backup API создаёт копию, архив сохраняет SHA-256 файлов,
а restore проверяет имена/размеры/checksums и целостность БД до установки. Windows-пути в копии
переводятся в `/data/sources/...` и `/data/clips/...`. Existing destination никогда не перезаписывается.
При незавершённой/очередной задаче экспорт откажется работать; сначала разберите её состояние.
Browser-папка старого компьютера не переносится: авторизация хранится зашифрованной в таблице аккаунтов.

## 3. Публичная панель с HTTPS (необязательно)

Привяжите свой домен к VPS и обеспечьте доступ к портам 80/443. В `.env` установите:

```dotenv
SITE_DOMAIN=clips.your-domain.example
PUBLIC_BASE_URL=https://clips.your-domain.example
```

Затем:

```sh
python3 -m deploy.manage --https start
python3 -m deploy.manage --https status
```

Caddy получает сертификат для указанного домена. Если DNS/порты/выдача сертификата не работают,
используйте SSH-туннель, а не отключайте HTTPS. Если вернулись к туннелю, верните loopback PUBLIC_BASE_URL
и пересоздайте web/worker через start без `--https`. Также остановите старый proxy:
`docker compose -p clipforge-server -f compose.yml -f compose.https.yml stop proxy`
(до очистки SITE_DOMAIN). Для изменения `.env` нужен именно recreate/start,
а не простой restart. Не выставляйте порт 8001 на `0.0.0.0`.

## 4. Проверка после переноса

1. Убедитесь, что migrate завершился с кодом 0, web и worker healthy.
2. Пройдите `smoke`: реальный FFmpeg и Chrome/Xvfb/sandbox, но без доступа к внешним сайтам/публикации.
3. Войдите в панель, проверьте импортированные аккаунты, файлы и историю ранее сохранённого тестового видео.
4. Кнопкой проверки подтвердите сессию Studio. Новый IP может вызвать ручную проверку Google.
5. Сделайте один новый разрешённый тестовый клип, выберите «Только я» и явно подтвердите загрузку.
   Не повторяйте уже отправленный файл. Успех — подтверждённое сохранение в Studio и ссылка,
   не HTTP 202/статус uploading. Не пропускайте CAPTCHA/2FA.
6. Отдельно проверьте поиск → y2save → монтаж → загрузка. Работа стороннего y2save не гарантирована;
   его ошибка должна оставаться ошибкой, а не ложным успехом. Права на исходник должны быть подтверждены.

Дополнительные read-only проверки сети/сессий доступны через `deploy.acceptance`:

```sh
docker compose run --rm --no-deps worker tools xvfb-run -a python -m deploy.acceptance --network --search --session
```

Они не загружают видео на YouTube. Проверка `--downloader` проверяет только форму y2save;
`--download` дополнительно скачивает один короткий CC-исходник в временную папку и монтирует
пятисекундный клип, без публикации. Временные медиа удаляются после теста. Для `--download`
нужен рабочий ключ поиска; результаты внешних сервисов зависят от их состояния.

Этот проект не создаёт аккаунты, не обходит проверки и не заменяет ручное восстановление сессий.
На VPS нет вашего Happ: проверьте сетевой доступ отдельно; настройки Happ на локальном ПК не меняются.

TikTok Studio может вернуть HTTP 200, содержащий внутреннюю ошибку
`ResponseMetadata.Error.CodeN=30522` (`Policy requirements, request blocked`).
Это отказ платформы на этапе подготовки загрузки, а не успешная передача файла.
Сервис наблюдает ответы обычной страницы, сохраняет только распознанный код,
останавливает задачу до Post и требует проверки владельцем. Причина применения
политики (аккаунт, сессия, сеть или другое условие) из этого ответа не следует.
Отказ 30522 отображается как ошибка платформы (`error`), а не как неверная сессия
(`reauth_required`). Кнопка проверки ждёт поздний ответ разрешений Studio;
само открытие формы ещё не подтверждает возможность отправить видео.
Не подменяйте cookie, подписи запросов или IP ради обхода; проверьте доступность
обычной загрузки в своём браузере либо обратитесь в поддержку с кодом ошибки.

## 5. Резервные копии, обновления и откат

```sh
python3 -m deploy.manage backup
python3 -m deploy.manage logs
```

Backup временно останавливает web/worker и затем возвращает их. Выполняйте его при пустой очереди:
если есть queued/processing задачи, он откажется, не отменяя их. При HTTPS добавляйте `--https`.
Архив создаётся в `backups/` и содержит приватные данные. Отдельно безопасно храните APP_SECRET:
он намеренно не включён в backup. Копируйте проверенные backups вне VPS, контролируйте свободный диск.
Копия архива также остаётся в `/data/backups`; очистку/политику хранения задайте отдельно.
При restore нужны место под архив, staging и конечные видео: tmpfs для больших медиа не используется.
Сохраните расписание backup во внешнем планировщике своего сервера; автоматический планировщик здесь не устанавливается.

Для восстановления используйте новый Compose project/пустой volume, например:

```sh
python3 -m deploy.manage --project clipforge-restore restore --archive /PRIVATE/backup.zip
```

Перед стартом восстановленного проекта остановите старые web/worker, чтобы не было двух независимых
публикаторов и конфликта порта. Старый volume и исходный компьютер оставьте для отката. Не выполняйте
`docker compose down -v`. Restore не удаляет/перезаписывает прежние базы. Полный restore drill на
целевом сервере обязателен: тест на временных копиях не заменяет проверку ваших реальных backups.

Перед обновлением: пустая очередь → backup → сохранение текущего release-manifest/образа → новая
сборка → миграции → smoke → проверка одной приватной загрузки. Downgrade новых миграций специально
не удаляет историю отправок: для отката восстановите verified backup и соответствующий старый код
в новом volume. Не используйте новый код с произвольно старой схемой.

## Остановка и восстановление подготовки (v40)

Операция остановленного плана завершается с `automation_stopped`, без автоматического повтора. Техническая ошибка уже выполнявшейся операции также не создаёт новый повтор после остановки. Ожидающие задания отменяются с очисткой времени повтора. Архивные задания не участвуют в проверке занятого конвейера.

Явный запуск партии может заново начать подготовку, если прежний поиск завершился, а скачивание остановлено до создания/резервирования клипа и отправки. Поддержано старое сообщение об остановленном режиме без нового кода. Для ошибки длины исходника повтор разрешён после изменения настроек монтажа. Старые задания сохраняются. Ошибки входа, ручных проверок и платформы, текущие операции и зарезервированные клипы не снимаются этой логикой. Панель заранее показывает причину блокировки для ожидающего или выполняющегося задания.


## Резервный загрузчик и неудачные исходники (v41)

В текущем интерфейсе Y2Save обнаружено рекламное окно `.s4k-ov` с кнопкой установки `.s4k-pri`, имеющей название Download. Загрузчик закрывает это окно через наблюдаемую кнопку Close и исключает его элементы из выбора файла. Отсутствие ссылки на готовое видео продолжает ожидание конвертации. Реклама без известной кнопки закрытия не выбирается.

После отказа всех сервисов сохраняются обе попытки с безопасными описаниями причин без исходных ответов, URL и токенов. При исчерпании трёх попыток явный запуск новой подготовки может повторить поиск, если нет клипа, его резервации или отправки. Адрес с таким отказом пропускается в новом поиске 30 минут. Старые ошибки распознаются по прежнему сообщению. Ручные проверки и запрет автоматического обхода доступа сохраняются.


## Прямое скачивание (v42)

Сначала используется yt-dlp 2026.10.21 с yt-dlp-ejs 0.8.0 и уже установленным Node из Playwright. Затем — прежние сайты. Загрузка выполняется в отдельном процессе с общим пределом времени, без пользовательских cookie, импорта сессий или сторонних плагинов. Скрипты декодирования подписей установлены вместе с зависимостями; динамическое скачивание компонентов отключено. Вход, возрастные и региональные ограничения, запрос подтверждения человека останавливают скачивание. Живые эфиры не принимаются. Готовый файл проверяется FFprobe и переносится атомарно.

Временные файлы удаляются после ошибки и таймаута. Подробные ответы и подписанные адреса не сохраняются в журнале. VPN, системный DNS, учётные данные и файл настроек сервера не меняются. Новый порядок загрузчиков применяется по умолчанию, когда `DOWNLOAD_PROVIDER_ORDER` не задан.


## Автомонтаж v44

Новые задания с включённым автомонтажом получают профиль 2. Итоговый размер всегда
1080×1920, H.264/AAC, 30 fps; старые снимки настроек и готовые клипы сохраняются.
Фрагмент и результат — 10–15 секунд, скорость 0.95–1.05 с изменением на 1–5%, без 1.0. Из исходника
исключаются первые и последние 1–2 секунды, когда длины хватает; для короткого
10–12-секундного исходника поля уменьшаются, чтобы сохранить минимальную длину.

Зум 1–3%, мягкая цветокоррекция и баланс тепла, размытый фон, тонкая рамка,
минимальное зерно. Заголовок исходника появляется и исчезает в первые 3.2 секунды;
это заголовок, а не распознанные субтитры речи. Все параметры сохраняются до
кодирования. Повтор задания использует тот же клип и эффекты.

Перед зеркалом проверяются кадры всего выбранного отрывка с частотой 2 кадра/с
через локальный Tesseract (английский и русский). Обнаружение текста или ошибка
проверки отключают зеркало. OCR и выборка не гарантируют обнаружение каждой
надписи и не определяют все языки. OCR выполняется без блокировки записи базы.

Доступный трек из сохранённой библиотеки выбирается автоматически и заменяет
исходный звук. Если треков нет, сохраняется исходный звук с нормализацией,
лёгкой сменой тональности с компенсацией длины и плавным входом/выходом. В звуковую
дорожку добавляется очень тихий белый шум. Немое видео остаётся немым, если
музыки нет. Звуки TikTok автоматически не выбираются и не скачиваются.

Исходные глобальные и потоковые метаданные и главы не копируются. MP4 получает
служебные поля нового кодека/контейнера. Монтаж меняет файл, но не гарантирует
признания оригинальным платформой и не заменяет разрешение на использование.
Фильтры и экранирование сверены с официальной документацией FFmpeg:
https://ffmpeg.org/ffmpeg-filters.html и https://ffmpeg.org/ffmpeg.html.

## Почасовые просмотры аккаунтов (v45)

Верхняя вкладка «Просмотры · каждый час» открывает счётчики всех сохранённых
TikTok web-аккаунтов. Сбор работает в отдельном потоке рабочего веб-сервиса,
независимо от включения плана публикаций и открытой страницы. Новые аккаунты
подхватываются автоматически. Для каждого сохраняются точные просмотры всех
доступных в Studio роликов, их количество, последний успешный замер и следующая
проверка. Изменение сравнивается с предыдущим полным замером того же профиля.
Время в интерфейсе — Москва. История замеров хранится 30 дней.

Используется обычная страница TikTok Studio Posts. Наблюдаются только ответы
`/tiktok/creator/manage/item_list/v1/`, которые запрашивает сам интерфейс.
Сохраняются только числовые счётчики; подписанные ссылки, полные ответы и cookie
в статистику не попадают. Ролики объединяются по идентификатору, повторы страниц
не суммируются. Прокрутка позволяет Studio загрузить следующую страницу. Если
конец списка не подтверждён, результат отмечается неполным. Нет данных — «—»;
ноль появляется только после успешного ответа Studio. Удалённые и недоступные
ролики в сумму не входят; это не показатель просмотров удалённых видео за всю жизнь аккаунта.

Расписание и пятиминутная аренда проверки сохраняются в отдельных таблицах
`account_views` / `account_view_samples` (миграция `0011_account_views`).
Перезапуск не сбрасывает почасовой интервал; просроченная аренда восстанавливается.
Одновременно проверяется один аккаунт. Аккаунт с ожидающей или выполняющейся
операцией пропускается до завершения этой операции. Ошибка не стирает прошлые
цифры. При требовании входа/ручной проверки автоповтор останавливается до обновления
сохранённой сессии. Известные недоступные аккаунты не проверяются автоматически.
Кнопка «Обновить сейчас» ставит проверку в очередь, но не повторяет аккаунты,
проверенные меньше пяти минут назад. Проверка статистики не запускает публикации.

Автосбор включён по умолчанию на рабочем сервере; `ACCOUNT_VIEWS_ENABLED=false`
отключает его для испытательных сред. Тесты обычного набора не обращаются к TikTok.
